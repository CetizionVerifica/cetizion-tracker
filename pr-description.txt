SALES REPORT — WHAT EACH SECTION SHOWS
(in simple words, for review)

---------------------------------------------------------------
1. SECTOR REPORT
---------------------------------------------------------------
Shows, for each sector (industry): how many enquiries came in, how many
quotations were won, lost, or are still open (pipeline), and the total
value won.

- Enquiries are counted by the date the enquiry was logged.
- Won/lost/pipeline are counted by the date the deal was actually decided
  (recently fixed — see note at the bottom).

---------------------------------------------------------------
2. CLIENT REPORT (Repeat vs Single-enquiry clients)
---------------------------------------------------------------
Shows the same numbers as above, but grouped by client instead of sector.
A client with 2 or more won POs (at any time up to the end of the chosen
date range) is marked "Repeat client"; everyone else is "Single enquiry
client."

This is the section where the Midal issue showed up (enquiry counted,
but the PO didn't) — now fixed.

---------------------------------------------------------------
3. FX REPORT
---------------------------------------------------------------
Shows only the won POs billed in a foreign currency (not INR) — how many,
their value in that currency, and their value converted to INR using the
exchange rate on record.

---------------------------------------------------------------
4. REVENUE REPORT — three separate boxes, built from two different places
---------------------------------------------------------------

  a) ORDER INTAKE (by month)
     Counts QUOTATIONS marked "Won." This is "how many deals did we win,"
     dated by when the quotation itself was originally sent out.

  b) INVOICING & COLLECTIONS (by month)
     Counts actual entries in the PO REGISTER (the Purchase Orders page) —
     a completely different table. Shows PO value, what's been invoiced,
     what's been received, and what's still due. Dated by the PO's own
     date.

  c) PAYMENT STATUS
     Same PO Register entries as (b), just grouped by their payment status
     instead of by month (Overdue, To Invoice, Pending, Fully Paid, etc.)

  WHY (a) AND (b)/(c) CAN SHOW DIFFERENT "PO" COUNTS:
  - (a) counts a WON DEAL. (b)/(c) count an actual PO PAPER registered
    in the system. One deal can end up with several POs, or with none
    registered yet — so the two numbers are not expected to always match.
  - They use different dates: (a) uses the quotation's date, (b)/(c) use
    the PO's own date. A deal won in one month can have its PO paperwork
    dated a different month.
  - A PO with no date filled in is left out of (b) and (c) entirely
    (there's a warning banner for this on the page), but still counted
    in (a) if the underlying quotation is marked Won.

  QUESTION FOR YOU: should "Orders won" and the Payment section's "POs"
  always mean the same thing, or is it fine that they answer different
  questions ("deals won" vs "paperwork registered")? If you want them to
  match, the fix is either a data-entry rule (always register the PO with
  a date when a deal is won) or a change to how the report counts —
  let me know which you'd prefer.

---------------------------------------------------------------
RECENT FIX — Client/Sector/FX report "PO" counting
---------------------------------------------------------------
Before: a won deal was placed in a date range by the date the ORIGINAL
QUOTATION was sent — so if a quote was sent in one period but only won
weeks or months later, it could vanish from every period's PO count.

Now: a won deal is placed by the date it was ACTUALLY won, matching your
instruction — "if the PO is received, it should count, regardless of
date."

This only changed the Client, Sector and FX sections above. The Revenue
report's "Order intake" box (4a) was left as-is, since it's explicitly
labelled "by quotation date" — that's a separate decision, covered in the
question above.
